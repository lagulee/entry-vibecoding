## 1. 원본 작품 분석 (hex.ent)

원본은 4×4 헥스 보드 그림 위에 칸 오브젝트 16개를 올린 형태였습니다. 블록을 모두 풀어 본 결과:

| # | 문제 | 원본 상태 |
|---|---|---|
| 1 | **승리 판정이 없음** | `4*4보드` 의 조건문이 비어 있고, 조각난 블록(떨어진 `만일`, `승_패 = 빨강`)만 남아 있음 → 끝까지 두어도 게임이 끝나지 않음 |
| 2 | 다시하기가 보드를 지우지 않음 | `원1`~`원16` 변수와 모양이 초기화되지 않아 두 번째 판부터 이전 돌이 남음 |
| 3 | 이미 놓인 칸을 다시 누를 수 있음 | 칸마다 `계속 반복` 안에서 클릭을 검사, 놓은 뒤 `반복 중단` 으로만 막음 → 장면을 다시 시작하면 꼬임 |
| 4 | 1인 모드·5×5 미완성 | 누르면 "미완성" 말풍선만 나옴 |
| 5 | 차례 표시가 글자만 | `차례` 변수 값(빨강/파랑)을 그대로 씀, 첫 화면에서는 `0` 표시 |
| 6 | 디자인 | 캡처한 JPG 보드, 기본 글꼴 글상자 버튼, 회전된 텍스트 썸네일 |
| 7 | 구조 | 똑같은 스크립트를 칸 16개에 복사 → 수정이 어렵고 보드 크기를 늘릴 수 없음 |

## 2. 새 HEX 에서 달라진 점

| 영역 | 새 작품 |
|---|---|
| 게임 규칙 | 표준 헥스 규칙. 빨강 선공, 빈 칸 하나씩, 무승부 없음. **승리 판정 = 최단 거리 0** (아래 AI 와 같은 거리 지도 계산) |
| 보드 | 5×5 · 7×7 · 9×9. 칸 81개를 **복제본 하나**로 처리 (원본은 칸마다 오브젝트) |
| 대전 방식 | **AI 대전**(쉬움·보통·어려움, 내 색 선택) · **2인 대전** |
| 편의 기능 | 무르기(AI 대전은 내 수까지 두 수), **힌트**(어려움 AI 가 추천 수 표시), 새 대국, 설정 · 메뉴, 빠른 대국 |
| 연출 | 놓을 곳 미리보기, 돌이 톡 튀어나오는 효과, 마지막 수 표시, **이긴 길 반짝임**, 결과 배너, 축하 조각, AI 생각 중 표시 |
| 소리 | 코드로 합성한 효과음 7개(돌 놓기 2종, 버튼, 무르기, 승리, 패배, 대국 시작) |
| 디자인 | 어두운 남색 + 빨강/파랑 네온 테마, 2배 해상도 그림(선명함), 좌표 표시(A~I, 1~9), 오른쪽 정보 패널 |
| 안내 | 게임 방법 화면(목표 · 브리지 비법 · 조작), 타이틀에 난이도별 AI 전적 |

## 3. AI 설계

AI 는 헥스 프로그램들이 쓰는 **거리 지도(shortest-path) 평가**를 엔트리 블록으로 옮겼습니다.
기준 구현은 [`tools/hex_ai.js`](../tools/hex_ai.js) 이고, 엔트리 블록 AI 는 이것과 **같은 수를 둡니다**(테스트로 확인).

1. **거리 지도**: 한쪽 변에서 각 칸까지 "더 놓아야 하는 돌 수". 내 돌 0 · 빈 칸 1 · 상대 돌 막힘.
   보통·어려움은 **브리지**(사이 빈 칸 2개)와 **변 템플릿**(둘째 줄 칸 + 변의 빈 칸 2개)을 한 걸음으로 봅니다.
2. **점수**: 빈 칸 c 마다 `(내가 c 를 지나 잇는 최단 거리) + (상대가 c 를 지나 잇는 최단 거리)` → 가장 작은 칸.
   내 길을 넓히면서 상대 길을 막는 칸입니다.
3. **규칙** (위에서부터): 첫 수 가운데 → 바로 이기는 칸 → 상대가 바로 이기는 칸 막기 → (어려움) 끊긴 브리지 잇기 → 점수
4. **어려움 1수 탐색**: 점수 상위 5칸에 실제로 두어 보고 `상대 최단 거리 − 내 최단 거리` 가 가장 큰 칸.

| 난이도 | 브리지 거리 | 흔들기(무작위) | 브리지 지키기 | 1수 탐색 |
|---|---|---|---|---|
| 쉬움 | ✗ | 0~3 | ✗ | ✗ |
| 보통 | ✓ | 0~1 | ✗ | ✗ |
| 어려움 | ✓ | 0~0.25 | ✓ | 상위 5칸 |

기준 구현끼리 대결 (`npm run hex:test:ai`, 색 번갈아 20판):

| 보드 | 쉬움 vs 무작위 | 보통 vs 쉬움 | 어려움 vs 쉬움 | 어려움 vs 보통 |
|---|---|---|---|---|
| 5×5 | 20/20 | 16/20 | 19/20 | 10/20 (5×5 는 선공이 절대 유리) |
| 7×7 | 20/20 | 18/20 | 19/20 | 13/20 |
| 9×9 | 20/20 | 19/20 | 20/20 | 19/20 |

### 엔트리에서 빠르게 돌리기

| 문제 | 해결 |
|---|---|
| 엔트리 `반복하기` 는 **한 바퀴마다 한 프레임** 쉼 (함수 안에서도) → 칸 81개 BFS 는 81프레임 | 칸마다 이완 계산을 **펼쳐서** 한 프레임에 보드 전체를 한 번 훑음 (앞→뒤, 뒤→앞). 값이 안 바뀔 때까지 반복 = 보통 3~6프레임 |
| 빨강/파랑 × 양쪽 변 × 보드 3종 = 12가지 코드 | 육각 보드는 전치(r↔q)·180° 회전에 대해 모양이 같음 → **9×9 표준 격자 코드 하나** + 칸 번호 변환표(`순서` 리스트). 작은 보드는 격자 왼쪽 위에 놓고 바깥은 막힌 칸 |
| 일반 변수는 값이 바뀔 때마다 표시 계산 | 거리·비용은 **함수 지역 변수**(d1~d81, w1~w81, e1~e81) |
| 리스트 0번째 항목을 읽으면 작품이 멈춤 | `그리고` 는 양쪽을 다 계산하므로 `만일` 을 겹쳐서 막음 |
| AI 계산 중 새 대국/무르기 | THINK · HINT · CHECK 상태에서는 버튼 비활성, 게임 번호 확인 후에만 돌을 놓음 |

## 4. 검증 (실제 entryjs 4.0.23 엔진)

`npm run hex:test:entry` — `.ent` 를 실제 엔트리 엔진에 불러와 마우스로 클릭하며 확인합니다.

**33 / 33 통과** (`tools/test/harness/hex_suite.js`)

| 묶음 | 확인한 것 |
|---|---|
| 화면 흐름 | 타이틀 → 게임 방법 → 타이틀 → 대국 설정 → 뒤로. 2인 대전을 고르면 난이도·색 버튼이 비활성 |
| 승리 판정 | 2인 5×5: 빨강 가로줄 → 빨강 승리, 파랑 세로줄 → 파랑 승리, **꺾인 대각선 연결**도 승리. 이긴 길 칸만 정확히 표시(5칸) |
| 입력 | 이미 놓인 칸 클릭 무시, 대국이 끝난 뒤 클릭·무르기 무시, **9×9 모든 칸(81개) 마우스 위치 → 칸 번호 일치** |
| 무르기 | 2인: 한 수, AI 대전: 내 수까지 두 수 |
| **AI == 기준 구현** | 기준 AI 끼리 둔 대국에서 뽑은 27국면 × 난이도 3 = **81/81 같은 수** (이기기 6 · 막기 9 · 브리지 지키기 1 · 점수 44 · 1수 탐색 21) |
| AI 대국 완주 | 5×5 어려움 · 7×7 보통(사람 파랑) · 9×9 어려움 끝까지 두기 → 엔진의 승자 == 기준 판정 |
| 힌트 | 힌트 칸 == 기준 AI(어려움) 추천 수, 그 칸에 두면 힌트 표시 사라짐 |
| 전적 | 2인 빨강/파랑 승수, AI 대전 난이도별 승·패 |
| 오류 | 엔트리 오류 알림(toast)·페이지 오류 0 |

AI 한 수 계산 시간 (테스트 환경, 최대값, 연출용 0.3초 대기 포함):

| 보드 | 쉬움 | 보통 | 어려움 |
|---|---|---|---|
| 5×5 | 0.7초 | 0.9초 | 1.6초 |
| 7×7 | 0.9초 | 1.4초 | 2.5초 |
| 9×9 | 1.2초 | 1.7초 | 3.1초 |

## 5. 파일

```
dist/HEX.ent               완성 작품 (playentry.org → 작품 만들기 → 오프라인 작품 불러오기)
assets/hex/                그림(2배 해상도 PNG) · 효과음(MP3) — tools/hex_art.js, tools/hex_sound.js 가 생성
tools/build_hex.js         작품 조립 (entrygen DSL) + .ent 패키징
tools/hex_ai.js            기준 AI (JS) — 엔트리 블록 AI 와 같은 알고리즘
tools/hex_canon.js         9×9 표준 격자 변환표, 검증용 JS 구현
tools/hex_geom.js          보드 기하 (이웃 · 브리지 · 변 템플릿)
tools/hex_layout.js        화면 배치
tools/test/hex_*.js        변환표 검증, AI 대국 테스트
tools/test/harness/hex_suite.js  실제 엔진 테스트
docs/HEX_BLOCKS.md         작품의 모든 블록 (엔트리 블록 문구)
```

```bash
npm install && npm run test:setup   # 최초 1회
npm run hex:art        # (선택) 그림 · 효과음 다시 만들기
npm run hex:build      # dist/HEX.ent + docs/HEX_BLOCKS.md
npm run hex:test:ai    # 변환표 == 기준 AI, 난이도별 대국
npm run hex:test:entry # 실제 엔진 테스트
```

## 6. 스태프 선정 · 인기 작품을 위한 업로드 가이드

- **작품 이름**: `HEX 헥스 — AI와 두는 육각 연결 전략 게임`
- **작품 설명 예시**
  > 빨강은 왼쪽↔오른쪽, 파랑은 위↔아래! 먼저 이으면 이기는 헥스 게임입니다.
  > 🤖 AI 대전 (쉬움·보통·어려움) / 👥 2인 대전 / 5×5 · 7×7 · 9×9 보드
  > 💡 막히면 힌트, ↶ 무르기도 있어요. AI 어려움을 이긴 사람은 댓글로 인증해 주세요!
  > 헥스는 수학자 존 내시도 연구한 게임으로, 무승부가 절대 나오지 않아요.
- **태그**: 게임, 보드게임, 전략, AI, 헥스, 2인용
- **썸네일**: 작품을 저장할 때 첫 화면(타이틀)이 썸네일이 됩니다. 저장 전에 ▶ 시작하기로 타이틀이 보이게 해 두세요.
- 스태프 선정은 **완성도 · 독창성 · 디자인 · 설명**을 봅니다. 이 작품은 AI 가 실제 알고리즘으로 동작하고, 게임 방법 화면과 난이도 선택이 있어 처음 보는 사람도 바로 즐길 수 있습니다.
- 공개 후에는 댓글에 "AI 어려움 9×9 몇 수 만에 이겼는지" 같은 **도전 과제**를 걸면 참여가 늘어납니다.

## 7. 한계
